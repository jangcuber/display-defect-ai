# 디스플레이 결함 데이터 확보 가능성과 평가 설계

조사 기준일: 2026-10-13 UTC. **데이터는 아직 확보하지 않았으며, 이 문서는 후보 조사와 설계 제안입니다.**

## 먼저 할 일

- **AnoLCD를 조건부 주 후보로 검토합니다.** 디스플레이 이상 탐지에 적합하지만 공식 파일 접근,
  프로젝트 이용 허락, 실제 마스크는 미확인입니다. 다운로드 가능한 무료 데이터로 확정하지 않습니다.
- 이용 조건과 공식 접근 경로를 확인한 뒤 작은 이미지·마스크 샘플을 검사합니다. 조건이 맞지 않으면
  데이터 미확보로 보고하고 범위를 다시 결정합니다. 제한 우회나 비공식 미러는 해결책으로 삼지 않습니다.
- 정상 전용 학습을 유지하고 **공식 test의 정상·결함 이미지를 모두 학습·개발·보정에서 제외**합니다.
- 아래 분할 수, 정상 오탐 목표 5%, 픽셀 분위수와 비교 실험 수는 **미승인 제안**입니다.
  성공 기준이나 성능 보증이 아니며 데이터·그룹·연산 확인 후 별도로 정합니다.
- 실제 담당과 일정은 [역할 문서](../ownership.md), [프로젝트 계획](../plan.md)을 따릅니다.

## 2. 확보 후 최소 검사 — 아직 실행하지 않음

진행 전에 프로젝트 이용에 적용되는 명시적 조건, 현재 승인 범위에 맞는 공식 접근 경로,
작은 이미지·마스크의 정상 열림, 원본 split 목록을 확인합니다. 가입·정보 제출·추가 동의·저자 문의가
필요하면 별도로 결정합니다. 이 문서는 다운로드나 동의 권한을 부여하지 않습니다.

허용된 개별 파일 경로가 있으면 정상 2장과 결함 유형별 이미지·마스크 1쌍씩, 최대 약 20 MB를
초기 확인 범위로 제안합니다. 전체 ZIP만 제공되면 작은 샘플 검사와 전체 다운로드를 같은 일로 보지 않고
용량과 조건을 다시 검토합니다. 샘플은 비공개 데이터 디렉터리에 두고 공개 Git·문서·데모 자산에 복사하지 않습니다.

1. 실제 크기·채널·비트 깊이·읽기 오류와 이미지-마스크 파일 대응을 확인합니다.
2. 마스크 크기·좌표, 클래스 ID/팔레트, 배경·ignore 값, 이진/다중 클래스 여부를 확인합니다.
   VOC라는 설명만으로 인덱스나 색을 추정하지 않습니다.
3. 정상 마스크 없음과 빈 마스크를 구별합니다. 결함의 누락 마스크를 정상으로 취급하지 않습니다.
   정상용 0 마스크를 생성하면 파생물임을 기록합니다.
4. 작은 결함·희미한 경계·다중 결함·경계 밖 주석을 비공개 로컬 오버레이로 확인합니다.
5. 평가 담당은 test 샘플의 형식 확인 목적과 파일 ID를 기록합니다. 그 관찰을 모델 튜닝에 사용하지 않습니다.

샘플 통과는 전체 품질을 보장하지 않습니다. 정식 사용 결정 후 전체 파일 대응·해시·마스크 값 검사가 필요합니다.

## 3. AnoLCD 분할과 누출 방지

다음 수량은 공식 정상 train 2,100장이 확인되고 중복·그룹 문제가 해결된 경우의 **분할 제안**입니다.
확정된 데이터 수나 사용자 승인 조건이 아닙니다. 물리 패널·촬영 세션 그룹을 우선하면 수량이 달라집니다.

| 역할 | 원본 범위 | 제안 수량 | 허용 용도 |
| --- | --- | ---: | --- |
| train | 공식 정상 train | 1,470 | 정상 분포·특징 학습, 학습 통계, 증강 |
| val_dev | 공식 정상 train | 210 | 실행 안정성·정상 점수 분포 검사, 사전 지정한 소수 설정 검토 |
| val_cal | 공식 정상 train | 420 | 최종 모델의 임계값 보정만 |
| test | 공식 test 전체 | 정상 350 + 결함 750 | 설정과 임계값 고정 후 최종 평가 |

**공식 test의 정상도 결함도 train, val_dev, val_cal로 옮기지 않습니다.** 결함 검증 세트가 없으므로
정상 검증만으로 결함 검출력이 최적인 모델을 골랐다고 말할 수 없습니다. 단일 기존 baseline을 우선하고
비교 설정이 필요하면 작은 범위로 사전 합의합니다. test F1로 epoch·모델을 선택하지 않습니다.

가능하면 화면 범주 비율을 유지하고 seed와 목록을 고정합니다. 같은 패널·세션·연속 프레임과 그 crop/증강은
같은 split에 둡니다. 그룹 ID가 없으면 unknown으로 기록하고 독립성을 보장한다고 쓰지 않습니다.

파일 SHA-256, 디코딩된 픽셀 해시, 지각 해시 등의 근접 중복 후보 수동 확인 순으로 누출을 조사합니다.
파일명이 달라도 같은 표본일 수 있습니다. train/test 중복·동일 패널 후보를 보고하고, 문제가 있으면
test를 조용히 삭제하거나 이동하지 않습니다. 원본 평가와 오염을 통제한 별도 평가를 구분하고
겹치는 train 그룹 제거 등 조치를 명시합니다. 통계·정규화·특징 메모리·증강·합성 결함의 원본은 train만 씁니다.
test 마스크로 ROI나 후처리 규칙을 만들지 않습니다.

MSD로 전환하면 제공된 train/val/test 목록을 먼저 검증합니다. 6:2:2는 산술적으로 720/240/240이지만
실제 목록과 중복 확인 전에는 확정하지 않습니다. 학습 결함·마스크를 쓰는 지도 분할은 AnoLCD 정상 전용
설계와 다른 연구 질문이므로 별도 결정이 필요합니다. 정상 20장은 견고한 오탐 평가에 부족할 수 있으며
소속·중복·용도를 확인하기 전에 임의로 test에 섞지 않습니다.

## 4. 임계값 보정 제안과 인터페이스 경계

점수가 클수록 이상이라는 방향, 전처리, heatmap 집계, 모델·해상도·후처리를 val_cal 전에 고정합니다.
**정상 이미지 오탐 목표 5%는 검토용 운영점 예시이며 아직 채택하지 않았습니다.** 산업 보증이나 필수 합격선이 아닙니다.

조사에서 제안한 규칙은 독립 정상 보정 점수 n개를 정렬하고 `k = ceil((n + 1) × 0.95)`번째 값을
경계 q로 삼아 `score > q`일 때 이상으로 보는 방식입니다. 제안 수량 n=420이면 k=400입니다.
k가 n보다 크면 이 규칙으로 유한한 경계를 구할 수 없다고 기록합니다.

현재 [인터페이스 v1](../interface.md)은 **`score > calibration.threshold`**를 사용합니다.
따라서 이 보정 규칙을 채택하면 q를 threshold에 그대로 저장하고, 동점은 normal로 판정합니다.
임계값을 다음 부동소수점 값으로 옮기는 변환은 필요하지 않습니다. 실행 기록에 경계 q, 비교 연산,
계산 정밀도를 남기고 저장·복원 전후 경계 테스트를 확인합니다. 비교 규칙은 코드에 반영되어 있지만
실제 보정기는 아직 구현되지 않았습니다. 이 일관성 수정은 5% 목표나 분위수 정책의 채택을 뜻하지 않습니다.

정상 표본의 교환가능성을 가정한 분위수 규칙입니다. 패널 내 상관, 장비·화면 유형 변화가 있으면
목표 오탐률을 보장하지 않습니다. 범주 표본이 적으면 각 범주에 5% 보장을 주장하지 않습니다.
보정 세트로 모델·정책을 반복 선택하면 독립성이 깨지므로 새로운 절차가 필요합니다.

픽셀 임계값은 별도입니다. 정상 보정 이미지마다 같은 가중치를 주는 픽셀 점수 분포의 99.9% 분위수는
추가 검토 가능한 예시이며 채택된 수치가 아닙니다. 이미지 오탐 목표와 다르고 픽셀 상관 때문에 독립 표본
보장을 붙이지 않습니다. 모든 점수가 같은 퇴화 사례도 기록하며 test Dice로 임계값을 고르지 않습니다.

정상만으로 recall 95%를 맞출 수 없습니다. test ROC의 `FPR@95TPR`는 사후 연구용 요약이며 실제 운영
임계값으로 재사용하지 않습니다. test 전체 점수로 min-max 정규화한 뒤 임계값을 정하지 않습니다.
현재 합성 smoke 결과는 계속 `uncalibrated`이며 이 제안은 실제 보정 완료의 증거가 아닙니다.

## 5. 지표와 실패 사례

- 이미지: AUROC·AP, 고정 임계값 confusion matrix·precision·recall·F1·정상 FPR를 검토합니다.
  정확도 하나만 보고하지 않습니다. AP·precision은 결함 비율의 영향을 받으므로 제공자 설명상
  test 구성 750/1,100과 실제 확인한 수량을 함께 보고하며 현장 불량률로 외삽하지 않습니다.
- 위치: 실제 마스크가 검증된 경우 pixel AP·AUROC, 고정 픽셀 임계값 Dice/IoU를 검토합니다.
  큰 정상 배경 때문에 pixel AUROC만 보고 결론 내리지 않습니다. 결함 영상 macro Dice/IoU와
  정상 영상 오검출 면적 비율을 분리하고 빈 정답·빈 예측 규칙을 명시합니다.
- 범주: 결함 유형별 recall, 화면 범주별 표본 수·성능, 마스크 면적·대비별 오류를 봅니다.
  정상 표본이 없는 결함 단일 유형 집합의 이미지 AUROC 등 단일 클래스 지표는 N/A로 표시합니다.
- 불확실성: 필요하면 이미지 또는 알려진 패널 그룹 단위 bootstrap 신뢰구간을 구합니다.
  픽셀 수를 독립 표본 수로 세지 않으며 작은 하위집합 결과는 탐색 결과로 표시합니다.
- 실용성: 입력 크기, 장치, batch=1 예열 후 추론 시간, 메모리, 전처리 포함 여부를 기록합니다.
  현재 측정된 실제 모델 수치는 없습니다.

최종 test 후 FP/FN 상위 각 10개까지와 유형·크기별 대표 사례를 비공개 로컬에서 검토하는 방안을 제안합니다.
작고 낮은 대비의 결함, 모서리, 조명, 정상 질감, 마스크 불일치, 축소로 사라진 결함을 구별하고
원인·근거·한계를 기록합니다. 일부 사례는 교차 검토합니다. test 관찰로 수정하면 기존 결과는 개발에
사용된 결과이며 같은 test 개선치를 독립 최종 성능이라고 부르지 않습니다. 공개 보고에는 재배포 허락
없는 원본·마스크·오버레이를 넣지 않고 집계와 텍스트 분석만 둡니다.

## 6. 최소 manifest 제안

JSONL 한 행을 이미지 한 장으로 두고 공통 출처·조건은 별도 metadata에 기록하는 안입니다.
**실제 파일을 검사해 만든 manifest가 아닙니다.** [기존 데이터 원칙](../data.md)을 구체화하는 제안이며
데이터 로더나 수집 도구는 아직 구현하지 않았습니다.

| 이미지 행 필드 | 의미 |
| --- | --- |
| sample_id | 데이터셋 내부 고유 문자열; 추론 image_id와의 대응을 명시 |
| image_relpath, mask_relpath | 비공개 데이터 루트 기준 상대 경로; 마스크 없으면 null |
| image_sha256, mask_sha256 | 실제 바이트 해시; 없는 마스크 해시는 null |
| source_split | 제공자 원본 train / val / test |
| split | 프로젝트 train / val_dev / val_cal / test / quarantine |
| label, defect_type, screen_category | normal/anomaly; 유형·화면 범주 불명은 null |
| group_id | 물리 패널/촬영 그룹; 불명은 null, 파일명만으로 확정 금지 |
| width, height | 디코딩 후 양의 정수 |
| mask_status | present / absent_normal / missing / invalid |

공통 metadata는 dataset_id, version_or_snapshot, source_url, terms_url, terms_status(verified/pending),
verified_at, retrieved_at(미확보이면 null), split_seed, split_policy_version,
mask_encoding(class/background/ignore 값, 미검증이면 null)을 제안합니다.
이용 조건이 미확인이면 pending을 유지합니다. 실행 기록에는 manifest 해시, 모델·전처리 버전,
보정 표본 수, 임계값·비교 연산·계산 규칙을 연결합니다. 비밀번호·계정·인증 토큰·서명 URL은 넣지 않습니다.

검증할 사항은 ID 유일성, 상대 경로만 허용(`..`·절대 경로 금지), 실제 파일 해시, 이미지-마스크 크기,
라벨-마스크 상태 정합, 그룹의 split 간 중복입니다. AnoLCD의 source_split=test는 split=test 또는
문제 격리용 quarantine만 허용합니다. 격리 사유·개수를 기록해 test 제외를 숨기지 않습니다.
Git에는 스키마와 출처 설명만 두고 실제 manifest 공개는 경로·권리 검토 후 별도로 결정합니다.

## 7. 초보 팀원의 진행 순서

기존 역할과 일정 안에서, 데이터 조건 설명 → 작은 주석 검사 → 분할 목록과 누출 확인 → 단일 baseline
실행 → 검증 보정 → 설정 고정 → 최종 평가 순으로 진행합니다. 각 단계에서 입력·출력·실패 조건을
자기 말로 설명하고 다른 담당자의 검토를 받습니다. 데이터 확보 전에는 합성 입력으로 인터페이스를
연습하되 실제 성능 검증과 구분합니다. 새 데이터 수집·대량 수작업 라벨링·복잡한 논문 재현을 동시에
약속하지 않으며 이 문서는 담당 배정이나 일정을 변경하지 않습니다.
