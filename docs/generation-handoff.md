# 데이터 생성 → 모델 학습 인계

## 실행

저장소 루트, Python 3.10 이상(검증 환경 3.12.14):

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements/generation.txt
.venv/bin/python scripts/generate_dataset.py --output data/pilot-v1
.venv/bin/python scripts/check_dataset.py data/pilot-v1
.venv/bin/python scripts/check.py
```

이미 존재하는 출력 폴더는 덮어쓰지 않습니다. 재실행은 `--output data/pilot-v2`처럼 새 경로를 사용합니다.
표시할 이미지는 `--content /path/to/content.png`로 지정합니다. 기본값은 회색 180 화면입니다.
`--cases 30 --variants 2 --size 512 --seed 42`가 기본값입니다. 각 사례마다 정상/점/선을 생성합니다.
맥에서도 같은 명령을 사용하며 GUI 의존성이 없는 OpenCV headless를 설치합니다.

## 생성 모델

내용 이미지 → 사례별 패널 밝기/색감/완만한 밝기 편차 → 결함 주입 → 원근/흐림/노이즈 → PNG.
점은 밝거나 어두운 원, 선은 밝거나 어두운 수평/수직선 한 개입니다. 정상에는 결함이 없습니다.
같은 사례/변형 번호의 세 종류는 동일한 촬영 조건을 공유합니다. 결함 위치 마스크로 박스를 계산합니다.
AI 생성은 사용하지 않습니다. 프로그램이 결함을 통제하므로 정확한 자동 라벨을 만들기 쉽습니다.

원본 사례는 가상의 패널 한 개입니다. 30개 사례를 먼저 21/4/5개로 분리하고 각 사례의 모든 변형·종류를
같은 분할에 넣습니다. 표시 콘텐츠는 동일 화면 검사라는 목적상 모든 분할에서 공유합니다.
따라서 '미지의 콘텐츠에 대한 일반화' 시험은 아닙니다. 여러 실제 원본 사진/패널을 도입하면
물리 패널·촬영 세션·원본 사진을 묶은 영구 ID를 먼저 정하고 파생본 전체를 같은 분할에 넣어야 합니다.
데이터를 별도 실행으로 나눈 뒤 합치면 case ID가 재사용되므로 금지합니다.

## 결과와 형식

사용자 요청으로 최초 합성 묶음 `data/pilot-v1/`은 Git에 포함했습니다. 새 생성 데이터는 계속 gitignore 대상입니다.
맥에서 클론 후 `bash setup_mac.sh`로 의존성 설치·검증과 dataset.yaml의 로컬 절대 경로 설정을 수행하세요.
기존 묶음을 다시 생성할 필요는 없습니다.
YOLO 입력: `data/pilot-v1/dataset.yaml` (이동 시 절대 path 수정).
`images/`, `labels/`, `previews/`에 split별 파일이 있고, manifest.jsonl에 사례·조건,
generation.json에 seed/도구 버전/소요 시간이 있습니다. 상세 라벨 규격은 interface.md 참고.

클라우드 CPU에서 512×512 180장과 라벨·전체 미리보기 생성 약 4.55초(시작/의존성 설치 제외).
train 126장, val 24장, test 30장; 각 분할의 세 종류 수는 동일합니다.
검사기로 이미지 디코딩, 정상 빈 라벨, 클래스·박스 범위·픽셀 좌표 왕복, 파일 개수,
사례 분할 무중복을 확인했습니다. 정상·점·선 대표 미리보기를 시각 확인했습니다.
기존 통합 테스트는 39개 모두 통과, skip/expected failure 없음.

## 다음 작업과 한계

### 고정 구도의 흰색·검정 점·선 학습 데이터

흰색 정상 묶음(`--fixed-setup --normal-only`)이 준비된 뒤 아래 명령으로 한 번에 구성합니다.

```bash
.venv/bin/python scripts/generate_training_dataset.py --reference data/white-normal-fixed-v1 --output data/white-black-drive-yolo-v1
.venv/bin/python scripts/check_dataset.py data/white-black-drive-yolo-v1
```

패널마다 기존 흰색 정상과 새 검정 정상, 그리고 각 패턴의 점·선을 저장합니다. 모든 파생본은 원본 패널의 분할과 촬영 설정을 따릅니다. 흰 화면에는 RGB 전체 또는 일부 채널의 출력 저하를, 검정 화면에는 일부 출력이 켜진 채 유지되는 경우를 합성합니다.

같은 패턴의 정상본과 비교해 최대 채널 차이가 12 이상이고, 차이가 8 이상인 픽셀이 둘 이상인 경우에만 결함을 내보냅니다(8비트 기준). 박스는 달라진 픽셀을 감싸며, 끊긴 선은 한 박스로 묶습니다. 반대 패턴에서 픽셀이 동일한 경우는 정상 파일을 `visibility.jsonl`에서 참조합니다. 이 수치는 합성 샘플의 가시성 기준이며, 실제 촬영에서의 검출 한계는 별도로 확인해야 합니다.

### 모델 학습으로 넘기기

첫 학습 입력은 `data/white-drive-yolo-v1/dataset.yaml`입니다. 위 묶음의 흰 화면만 추출해
정상·점·선 각 1,000장과 기존 패널 분할을 보존했습니다. 분할별로 학습 2,100장, 검증 450장,
테스트 450장입니다.

첫 YOLO26n 학습은 맥 MPS에서 512픽셀 입력으로 6 epoch를 실행했습니다. 로컬 실행 설정과 가중치는
`outputs/yolo26n-white-v1/`에 있습니다. 검증 분할로 선택한 `train/weights/best.pt`를 테스트 450장에서
평가한 결과는 `test_metrics.json`에 기록했습니다. 테스트 AP50은 점 99.3%, 선 82.6%였습니다.
신뢰도 0.25와 IoU 0.50에서 점은 147/150개, 선은 130/150개를 찾았습니다.

선 개선 실험은 1·2픽셀 선을 더 자주 학습시키고 640픽셀 입력으로 4 epoch를 추가 실행했습니다.
검증에서 고른 설정은 선 신뢰도 0.15, 점 신뢰도 0.25, 선끼리의 중복 억제 IoU 0.25입니다.
동일 테스트에서 선 141/150개, 1픽셀 선 27/30개를 찾았고 같은 선의 중복 박스는 0개였습니다.
개선 가중치와 설정 비교는 `outputs/yolo26n-white-lines-v2/`에, 선 중복 억제 함수는
`src/display_defect_ai/line_postprocess.py`에 있습니다.

### OpenCV 규칙과 YOLO 비교

`src/display_defect_ai/opencv_baseline.py`는 고정 구도 512×512 흰 화면 한 장의 패널 영역에서
채널별 주변 밝기를 추정합니다. 주변보다 어두운 영역을 찾아 크기와 비율로 점·선을 구분하고,
같은 축에 놓인 선 조각은 한 박스로 묶습니다.

```bash
.venv/bin/python scripts/evaluate_opencv.py calibrate --dataset data/white-drive-yolo-v1 --output outputs/opencv-white-v1
.venv/bin/python scripts/evaluate_opencv.py compare --dataset data/white-drive-yolo-v1 --output outputs/opencv-white-v1 --yolo-run outputs/yolo26n-white-lines-v2
```

검증에서 선택한 8비트 밝기 차이 기준은 9, 박스 여유는 점·선 모두 1픽셀입니다.
같은 합성 테스트 450장에서 OpenCV는 점 150/150개, 선 150/150개, 1픽셀 선 30/30개를 찾았고
정상 오탐은 0/150장이었습니다. 개선 YOLO는 각각 149/150개, 141/150개, 27/30개, 0/150장이었습니다.
비교에는 동일 클래스와 IoU 0.50 이상을 적용했습니다. 실제 촬영과 복수 결함에서의 성능은 별도 평가가 필요합니다.

합성 영상은 반사·모아레·서브픽셀·센서·렌즈·불량의 물리 특성을 완전히 모사하지 않습니다.
실제 정상 사진과 결함 사례를 확보해 크기·대비·촬영 조건을 조정하고, 별도 실제 시험 자료로 평가해야 합니다.
이전 2종 묶음은 한 이미지당 결함 하나, 단순 배경, 사각 패널이며 복수 결함·복잡한 화면은 평가하지 않았습니다.
사각형이 존재해도 대비가 작은 배경에서는 결함이 안 보일 수 있습니다. 사용자 콘텐츠에서는 반드시
미리보기를 확인하세요. 현재 검사기는 구조를 검증하며 사람의 가시성 검토를 대체하지 않습니다.

## OLED 생산 직후 흰 화면 5종 확장

위 점·선 2종 데이터와 모델은 이전 비교 결과입니다. 새 데이터는
`data/oled-white-five-v1/`, 새 학습·검증·시험 결과는 `outputs/yolo26n-oled-five-v1/`에 저장합니다.

기본 종류는 어두운 점, 색 이상점, 가로선, 세로선, 어두운 영역입니다. 기존 정상 1,000장을
동일 픽셀과 원본 패널 분할로 재사용하고 각 주 종류별 불량 1,000장씩을 생성합니다.
총 6,000장은 학습 4,200장, 검증 900장, 시험 900장으로 나뉩니다.
주 종류가 점인 사진의 25% 확률로 2~4개의 군집점을 만들고, 불량 사진의 20% 확률로
겹치지 않는 추가 결함을 배치합니다. 군집점은 점 하나마다 박스를 붙이며 끊긴 선은 한 박스입니다.
실제 종류별 객체 수와 난수 시드, 촬영 조건은 `generation.json`과 `manifest.jsonl`에 기록합니다.

어두운 영역은 경계가 있는 국소 출력 저하를 모사합니다. 밝기·색 무라를 학습한 것으로 해석하지 않습니다.
RGB 채널별 출력 저하를 사용하며 OLED의 실제 서브픽셀 배열·광학 특성·회로 고장 원인을 완전히 모사하지 않습니다.
생성 명령, MPS 학습 및 검증·시험 명령은 README의 OLED 5종 절차를 따릅니다.

### 5종 학습과 로컬 시험 결과

2026년 11월 19일 Apple MPS에서 기존 개선 모델을 초기값으로 YOLO26n을 640픽셀 입력으로
8 epoch 학습했습니다. 학습 원본 4,200장에 얇은 선의 가중치를 적용한 목록은 5,149개 표본입니다.
모델은 검증 분할로 선택했고, 검증에서 고른 confidence는 어두운 점 0.25, 색 이상점 0.45,
가로선 0.06, 세로선 0.01, 어두운 영역 0.45입니다. 같은 방향 선의 중복 억제 IoU는 0.20,
OpenCV 밝기 차이 기준은 9입니다.

같은 종류와 IoU 0.50 이상을 기준으로 시험 900장을 평가했습니다. 복수 결함이 있으므로
아래 분모는 사진 수가 아닌 라벨 객체 수입니다.

| 종류 | OpenCV 검출 | YOLO 검출 |
|---|---:|---:|
| 어두운 점 | 271/271 | 271/271 |
| 색 이상점 | 236/237 | 236/237 |
| 가로선 | 186/186 | 180/186 |
| 세로선 | 179/179 | 176/179 |
| 어두운 영역 | 177/177 | 177/177 |

1픽셀 선은 OpenCV 64/64개, YOLO 56/64개를 찾았습니다. 정상 150장의 오탐은 둘 다 0장이며,
YOLO는 불량 사진에서 세로선 박스 1개를 추가로 검출했습니다. 불량 사진 750장 중 YOLO 단독의
사진 단위 미검출은 7장이고, 두 검출기의 OR 판정에서는 정상 오탐과 불량 사진 미검출이 모두 0장입니다.
복수 결함 사진 213장에서 모든 라벨 객체를 찾은 경우는 OpenCV 212장, YOLO 210장입니다.

초기 confidence 탐색 하한 0.08에서는 YOLO가 1픽셀 선 48/64개를 찾았습니다. 검증 자료에서
더 낮은 confidence의 후보를 확인한 뒤 탐색 범위를 0.01까지 확장해 최종 설정을 골랐습니다.
초기 결과는 `initial_validation_selection.json`, `initial_test_comparison.json`에 보존했습니다.
시험 900장은 이 조정 후 재평가한 자료이며, 실제 촬영 및 별도의 새로운 시험 자료로 확인해야 합니다.

맥 앱은 같은 가중치·검증 설정·후처리를 사용합니다. 실제 앱에서 정상 판정, 가로선과 어두운
영역의 동시 검출, 객체 번호·색·크기·밝기 차이의 표시를 확인했습니다. 기존 39개 테스트도 모두 통과했습니다.

### 1픽셀 선 개선: 다중 해상도 후보 결합

`outputs/yolo26n-oled-lines-v3/`는 기존 가중치의 640픽셀 추론과 960픽셀 선 후보를 결합합니다.
해상도를 높이면 약한 선의 confidence가 올라가지만 선 일부만 박스로 잡는 경우가 있어,
640픽셀의 낮은 confidence 후보와 축·두께·겹침을 확인한 뒤 길이 방향으로 합칩니다.
OpenCV 결과나 정답 라벨을 YOLO 박스 보정에 사용하지 않습니다.

별도 `outputs/yolo26n-oled-thin-v2/`에서는 학습 4,200장의 얇은 선 노출을 늘려 7,003개 표본으로
768픽셀·4 epoch 추가 학습을 완료했습니다. 640/768/960픽셀 검증에서 선·영역 성능이 안정적으로
개선되지 않아 앱에는 채택하지 않았습니다. 후보별 검증 비교는 `validation_experiments.json`에 보존합니다.

검증에서 고른 최종 confidence는 어두운 점 0.25, 색 이상점 0.45, 가로선 0.15,
세로선 0.35, 어두운 영역 0.45이고 선 중복 억제 IoU는 0.20입니다.
기본 입력은 640, 추가 선 입력은 960이며 OpenCV 설정은 기존과 같습니다.
설정을 고정한 뒤 기존과 같은 시험 900장·같은 종류·IoU 0.50 기준으로 비교했습니다.

| 항목 | 기존 YOLO | 개선 YOLO |
|---|---:|---:|
| 1픽셀 가로선 | 29/34 | 34/34 |
| 1픽셀 세로선 | 27/30 | 30/30 |
| 전체 가로선 | 180/186 | 186/186 |
| 전체 세로선 | 176/179 | 179/179 |
| 정상 화면 오탐 | 0/150장 | 0/150장 |
| 선 중복 박스 | 0개 | 0개 |
| 추가 오탐 박스 | 1개 | 0개 |
| 불량 사진 미검출 | 7/750장 | 0/750장 |

1픽셀 선 검출률은 87.5%에서 100%로 12.5%p 상승했습니다. 이전 미검출 8개를 모두 찾았고
기존에 찾던 1픽셀 선의 미검출 전환은 없습니다. 어두운 점 271/271, 색 이상점 236/237,
어두운 영역 177/177은 유지됐습니다. 복수 결함 사진의 전체 객체 검출은 210/213장에서
212/213장으로 증가했습니다. OpenCV 결과는 변하지 않았습니다.

데이터 manifest SHA-256은 `d72e5c2ad205bb10702b20262af368216882db30fe1c8052d4ec7bfb216cc872`,
기존·개선 가중치 SHA-256은 모두 `c755ff4ecbdb93f0639e566be4797ec9458eb0f3e777e550ebb19e1a85938e1a`입니다.
시험 이미지 ID 해시와 회복·퇴보 객체 목록은 `improvement_comparison.json`에 기록합니다.
`compare_oled_runs.py`가 캐시로 두 보고서를 재계산해 일치 여부를 확인하고 전후 PNG를 만듭니다.
시험 자료를 재사용한 합성 결과이며, 실제 촬영 성능은 별도 평가해야 합니다.

CPU 4스레드에서 같은 512픽셀 사진을 사용하고 모델 로드 후 1회 예열·3회 추론한 평균은
기존 25ms, 개선 68ms였습니다. 앱 시작·정렬·가중치 로드 시간은 제외한 수치이며
원시 측정값은 `inference_timing.json`에 저장합니다. 앱 빌드와 실제 검사 스크립트의
회복 가로선·정상 사진 검사를 통과했습니다. macOS는 재빌드로 서명이 바뀐 앱에 문서 폴더
접근을 다시 요청할 수 있으며, 접근 대기 중에는 Python 초기화 단계에서 검사 시간이 초과됩니다.
사용자가 접근을 허용한 뒤 앱에서 `case0087_white_horizontal_line.png`를 다시 열어,
시간 초과 없이 불량·가로선 판정과 OpenCV/개선 YOLO 각각 1개 박스 표시를 확인했습니다.

### 현실성 재검토와 차기 생성 기준 초안

현재 512×512 합성 데이터는 실제 패널 픽셀 피치·서브픽셀 배열·카메라 해상도의 대응을 정의하지
않았습니다. 기존 결과의 '1픽셀 선'은 생성 마스크의 두께이며, 실제 OLED 한 픽셀 결함의 검출
검증으로 해석할 수 없습니다. 점 예시는 반지름 6~7픽셀, 어두운 영역 예시는 RGB 출력 100%
저하를 골라 실제 목적을 대표하지 못했습니다. 기존 생성기는 큰 도형 안에 일정한 출력 저하를
적용하므로 완만한 영역 저하를 충분히 표현하지 못합니다.

다음 수치는 구현 전 검토용 실험 가정이며 산업 합격 기준이 아닙니다. 현재 데이터·가중치·
앱 설정은 교체하지 않았습니다.

- 물리 대응: 패널 모델·해상도·픽셀 피치·배열과 촬영 패널 ROI를 기록합니다. 예를 들어 패널이
  1920×1080이고 ROI가 5760×3240이면 축별 비율은 카메라 이미지 3픽셀/패널 1픽셀입니다.
  이 비율은 예시이며 광학 분해능을 보장하지 않습니다. 격자·1픽셀 패턴을 촬영해 중심과 모서리의
  실제 응답·흐림을 확인합니다. RGB/PenTile 배열은 모델 확인 전 임의로 고정하지 않습니다.
- 입력 해상도: 합성 원본을 실제 패널 좌표계에서 만들고 촬영 과정을 적용합니다. 미세 결함
  검사에서는 타일 등으로 유효 해상도를 보존하는 경로를 검증합니다. 전체 이미지를 640으로
  줄여 원래 작은 결함이 사라지는지 함께 확인합니다. 긴 선의 전체 길이도 별도로 평가합니다.
- 정상 변동: 구도·노출·초점·화이트밸런스를 고정하고 포화를 피합니다. 검토한 실제 정상 패널
  3~5개를 각 30회 촬영하는 초기 실험으로 시간 노이즈와 패널 간 공간 편차를 나눠 측정합니다.
  이 표본 수는 초기 계획이며 양산 보증을 위한 충분한 수라는 의미가 아닙니다.
- 정상 판정: 정상 표본의 분포는 측정 가능한 변동의 기준입니다. 제품 합격·불합격 기준은
  제조사/프로젝트 품질 요구와 경계 사례의 검토로 별도 결정해야 합니다. 통계상 드물다는 이유만으로
  불량으로 확정하지 않습니다. 크기·형태별 영역 통계와 사진 단위 오탐을 함께 검증합니다.
- 점/선 크기: 초기 실험은 패널 좌표의 점 1·2·3픽셀 크기, 선 1·2픽셀 폭으로 구분합니다.
  결함 마스크 크기, 촬영 후 결함의 유효 폭, 라벨 박스, 앱 표시 테두리를 각각 기록합니다.
- 대비: 선형화한 영상에서 정상 기준 대비 감소율을 정의하고, 결함 크기와 함께 1·2·3·5·10%
  등으로 나누어 측정 가능한 구간을 탐색합니다. 이 수치는 합격 기준이 아닙니다. 완전 소등도
  별도 강도 구간으로 취급하며 미약한 결함의 결과와 합산해 숨기지 않습니다. 응답을 보정하지 않은
  RGB 값 감소율을 실측 패널 휘도 감소율로 부르지 않습니다.
- 어두운 영역: 경계가 완만하고 내부 강도가 공간적으로 변하는 출력 저하를 별도 미리보기로
  만듭니다. `scripts/preview_soft_dark_region.py`와 `outputs/dark-region-soft-preview-v1/`는
  같은 정상 영상·구도·노이즈에서 최대 디지털 RGB 저하 5/10/15%를 비교한 초안입니다.
  `.venv/bin/python scripts/preview_soft_dark_region.py`로 생성하고,
  `artifacts/yolo-env/bin/python scripts/preview_soft_dark_region.py --render-only`로 비교 PNG를 만듭니다.
  기존 카메라 재현에는 원래 OpenCV 환경이 필요합니다. 이 미리보기는 학습 데이터에 포함하지 않았습니다.
- 비교: 패널/원본 단위로 분할하고 같은 정상 사진 오탐 조건에서 OpenCV와 YOLO를 비교합니다.
  크기×대비별 검출률, 정상 오탐, 중복과 전체 선의 위치 정확도를 따로 보고합니다.
  합성 정상 1,000장은 실제 정상 분포를 측정한 자료로 대체하지 않습니다.

### 짝지은 소형 점·얇은 선·완만한 영역 저하 미리보기

`scripts/generate_oled_paired_preview.py`는 전체 생성 전 검토용 정상 원본 3장과 불량 6장을
`outputs/oled-white-paired-v2-preview/`에 만듭니다. 기존 데이터·가중치·앱 설정은 보존합니다.
새 원본은 5888×3368이며, 합성 패널 1920×1080에 촬영 대응 3배·테두리 64픽셀을 적용한
명시적 가정입니다. 실제 패널/카메라를 측정한 설정은 아닙니다. 검토용 `split=preview`이며
실제 학습/검증/시험 분할에는 아직 포함하지 않았습니다.

정상 원본마다 밝기 수준·아주 작은 색/공간 편차와 노이즈 실현을 다르게 합니다. 구도·배율·
흐림·노이즈 표준편차는 고정하고, 같은 원본에서 파생된 모든 결함은 같은 노이즈 배열을
공유합니다. 정상 원본 0은 1×1픽셀 어두운 점/색 이상점, 원본 1은 폭 1픽셀 가로선/끊긴
세로선, 원본 2는 최대 3%/6%의 완만한 영역 저하 두 단계에 각각 사용합니다.
픽셀 단위는 합성 패널 좌표이며 %는 가정한 선형 디지털 RGB 값의 감소율입니다.

사진은 박스를 그리지 않은 원본이며, `pairs_01.png`와 `pairs_02.png`는 정상/결함 전체 사진과
같은 위치의 비교 크롭을 보여 줍니다. 점·선 크롭은 촬영 원본의 4배, 영역 크롭은 0.125배이며
밝기·대비를 강화하지 않습니다. 긴 원본 축소에서 작은 결함이 사라지는 현상을 숨기지 않습니다.
`pairs.json`은 정상-결함 관계와 크롭 위치를, `manifest.jsonl`은 원본 해시·좌표·속성을 기록합니다.
YOLO 라벨은 사진에서 짝 간 RGB 차이가 2 DN 이상인 영역의 박스이며, 더 약한 꼬리를 포함한
전체 변화 범위는 `observed_support_bbox`로 별도 기록합니다. 이 라벨 정책도 검토용입니다.

```bash
.venv/bin/python scripts/generate_oled_paired_preview.py
artifacts/yolo-env/bin/python scripts/generate_oled_paired_preview.py --render-only
```

생성은 기존 출력 폴더를 덮어쓰지 않습니다. `verification.json`에 중복·좌표·차이 마스크와
결함 전체 변화 범위 밖의 픽셀 일치 검증을 저장합니다. 전체 데이터 생성과 재학습은 아직
진행하지 않았으며, 고해상도 원본의 저장/타일 정책은 대량 생성 전에 결정해야 합니다.

### 일부 채널의 점진적 출력 저하 확장

`--profile channel-gradients`는 기존과 픽셀이 동일한 정상 원본 3장에 새 결함 21장을 더한
검토용 샘플입니다. R/G/B 단독, RG/RB/GB 동시, RGB 비대칭의 7개 조합을 작은 점·얇은 선·
완만한 영역에 각각 적용합니다. 출력 폴더는 `outputs/oled-white-channel-gradients-preview/`입니다.

1×1픽셀 점은 내부 공간을 더 나누지 않고 채널별 감소율을 다르게 합니다. 선은 폭 1픽셀을
유지하며 길이 방향으로 부드럽게 증가/감소/중앙 최대가 되는 감소율을 채널마다 지정합니다.
끊긴 선의 조각은 전체 선 좌표를 공유해 끊김 전후로 감소율이 연속됩니다. 이는 시간에 따른
깜빡임이 아니라 한 장 안의 공간적 변화입니다.

영역은 기본 완만한 출력 저하장에 채널별 지수를 적용해 저하 범위와 강도가 다르게 합니다.
예를 들어 R은 넓고 약하게, G는 좁고 강하게 낮아지도록 구성합니다. 기존 5종 라벨은 유지하며
영역의 채널/강도/공간 분포를 `channel_strengths`, `channel_profiles` 속성으로 기록합니다.
`dark_region`은 이 샘플에서 부분 채널의 지역적 출력 저하도 포함하며, 전기적 원인을 뜻하지 않습니다.
실제 OLED 서브픽셀 배열과 광학 누화는 아직 모델링하지 않은 합성 가정입니다.

```bash
.venv/bin/python scripts/generate_oled_paired_preview.py --profile channel-gradients
.venv/bin/python scripts/check_oled_paired_preview.py outputs/oled-white-channel-gradients-preview
artifacts/yolo-env/bin/python scripts/generate_oled_paired_preview.py --profile channel-gradients --render-only
```

`index.html`에서 21쌍의 정상·결함 원본을 비교합니다. `channel_dots.png`는 작은 점의 채널 조합,
`channel_gradient_examples.png`는 영역의 채널별 범위와 같은 선 앞/중간/뒤의 변화입니다.
표시용 크롭은 위치·배율을 명시하고 대비를 강화하지 않습니다. 검증기는 원본 해시·라벨·짝 차이
마스크·변하지 않는 채널·변화 범위 밖의 픽셀 일치와 점진 분포의 수치 및 실제 사진 샘플 값을
확인합니다. 기존 기본 6쌍과 학습 자료·모델·앱 설정은 보존하며 전체 생성·재학습은 진행하지 않았습니다.

## 전체 짝 데이터 v2 생성

샘플 검토 후 사용자 요청에 따라 `data/oled-white-paired-v2/`를 생성합니다. 정상 원본 1,000개에서
각각 정상 1장, 단일 불량 5종 각 1장, 서로 다른 2~3종의 복합 불량 1장을 만들어 총 7,000장입니다.
종류별 1,000장이며 원본 700/150/150개를 먼저 분리해 학습 4,900장, 검증 1,050장, 시험 1,050장입니다.

정상은 디지털 밝기 수준 225~240, 작은 채널/기울기/완만한 공간 편차, 좌표별 Gaussian 노이즈
표준편차 0.6으로 다양화합니다. 구도·노출 모델·배율·흐림은 고정합니다. 실제 정상 허용 기준으로
검증된 수치가 아닌 합성 조건이며, 같은 원본의 모든 파생 사진은 같은 정상/노이즈를 공유합니다.

점은 합성 패널의 1·2·3픽셀 크기이며 1픽셀이 다수를 차지합니다. 일부는 2~4개의 군집점이고
점별로 라벨링합니다. 가로/세로선은 폭 1/2픽셀, 전체/부분/끊긴 형태를 분할 안에서 균형 있게
배치합니다. 색 이상점의 7가지 채널 조합과 선·영역의 회색을 포함한 8가지 조합, 약/중/강의
대비 구간도 각 분할에서 최대 1장 차이로 배분합니다. 영역 저하는 최대 10%의 디지털 감소이며
채널별 강도·퍼짐이 달라집니다. R/G/B의 변화는 가정한 RGB 출력 모델이며 실제 서브픽셀 배열과 다릅니다.
복합 불량의 종류 조합은 두 종류 10가지와 세 종류 10가지를 고르게 배분합니다.

### 저장 방식과 고해상도 보존

생성 전 여유 저장 공간은 약 16GB였으며, 7,000개의 5888×3368 원본 PNG를 모두 저장하면
수십 GB를 넘어갑니다. 데이터는 원본 촬영 해상도를 유지한 1024×1024 타일 7,000개를 실제 PNG로
저장하고, 전체 장면의 배경·노이즈·결함을 재현하는 조건을 함께 저장합니다. 타일은 축소 이미지가
아닙니다. 같은 원본의 7개 사진은 같은 위치에서 자릅니다. 복합 결함의 모든 종류가 타일 안에
보이도록 생성하며 긴 선은 타일 경계에서 잘릴 수 있어 이를 속성으로 기록합니다.

`source_cases.jsonl`은 원본별 정상 조건과 타일 범위, `manifest.jsonl`은 실제 이미지·라벨과
`scene_objects`를 담습니다. 렌더러 스냅샷·해시·NumPy/OpenCV 버전을 고정합니다. 노이즈는
사진 좌표마다 고정되고 흐림의 합산 순서도 고정되므로, 전체 PNG에서 잘라낸 같은 위치가 저장
타일과 픽셀 단위로 같습니다. 7,000개 전체 장면 PNG가 이미 저장돼 있다는 의미는 아닙니다.

```bash
.venv/bin/python scripts/generate_oled_full_dataset.py --output data/oled-white-paired-v2 --sources 1000
.venv/bin/python scripts/check_oled_full_dataset.py data/oled-white-paired-v2
artifacts/yolo-env/bin/python scripts/render_oled_full_review.py data/oled-white-paired-v2
.venv/bin/python scripts/export_oled_scene.py data/oled-white-paired-v2 panel0000_mixed --output outputs/exported-scene/panel0000_mixed.png
```

완료 폴더는 덮어쓰지 않습니다. 생성 중 원본별 결과를 저널에 기록해 중단 시 임시 폴더에
완료 결과를 보존합니다. PNG는 먼저 임시 파일에 쓴 뒤 옮깁니다. 사전 용량 추정과 3GiB의
최소 여유 공간 검사를 적용합니다. 전체 검증은 모든 PNG의 파일·픽셀 해시, 중복, source 분할,
라벨 좌표, 짝의 변경 범위/채널을 확인하고 선택한 20개 원본의 장면·객체 라벨을 다시 렌더링합니다.
검증 결과는 `verification.json`, 정상별 요약은 `normal_summary.json`입니다.

이 단락은 전체 데이터 생성 단계의 기록입니다. 이후 사용자 요청으로 마스크·학습·앱 통합을 진행했으며 아래 후속 인계를 참고합니다.

### 전체 생성 및 검증 결과

실제 PNG 7,000장(정상 1,000 + 단일 불량 5종 각 1,000 + 복합 1,000)과 라벨 9,053개를
생성했습니다. 학습/검증/시험은 4,900/1,050/1,050장이고, 전체 파일·픽셀 해시와 라벨 좌표,
정상 짝의 변경 범위·채널 검사를 통과했습니다. 중복과 원본별 분할 누출은 모두 0건입니다.
두 종류 복합 사진 500장, 세 종류 복합 사진 500장이며 20가지 종류 조합은 각 49~51장입니다.

객체 라벨 수는 어두운 점 2,268개, 색 이상점 2,284개, 가로선 1,498개, 세로선 1,503개,
영역 1,500개입니다. 군집점과 복합 불량 때문에 사진별 균형과 객체별 수는 다릅니다.
타일 경계를 넘는 객체는 1,029개이며 `clipped_by_tile`에 기록했습니다.
선택한 20개 원본 가족의 모든 장면·개별 객체 라벨을 다시 렌더링해 일치 여부를 확인했습니다.

`review/index.html`은 실제 생성한 타일의 정상·불량 비교와 확대본입니다. 선택한 원본의 정상·
복합·영역 장면을 `review/full/`에 5888×3368로 내보내고 각 장면의 같은 위치가 저장 타일과
정확히 일치함을 확인했습니다. 내보내기별 해시는 같은 이름의 JSON에 있습니다.
생성기와 렌더러의 실제 사용 버전도 `generator_snapshot.py`, `renderer_snapshot.py`로 보존했습니다.

정상 실행 결과와 모두 같은 것을 확인했습니다. 기존 39개 스모크 테스트도 통과했습니다.

## 픽셀 마스크·두 모델 비교·앱 통합 후속 인계

사용자 요청에 따라 같은 7,000개 타일에 5종 독립 비트 마스크를 추가했습니다.
`masks/{train,val,test}/`의 uint8 PNG에서 어두운 점=1, 색 이상점=2, 가로선=4,
세로선=8, 영역=16이며 겹친 픽셀은 비트 OR로 보존합니다. 정상은 전부 0입니다.
같은 정상에서 개별 결함만 렌더링한 최대 RGB 차이 ≥ 2 DN을 정답으로 사용합니다.
`mask_manifest.jsonl`, `segmentation.json`, `mask_verification.json`에 경로·해시·전체 검사를 기록했습니다.
기존 이미지·객체 라벨·원본 분할은 바꾸지 않았습니다.

```bash
.venv/bin/python scripts/generate_oled_masks.py data/oled-white-paired-v2
artifacts/yolo-env/bin/python scripts/render_pixel_masks.py
```

실험 경로는 `outputs/paired-model-comparison-v1/`입니다. U-Net은 186,805개 파라미터의
작은 픽셀 분할 모델이며 YOLO26n은 COCO 사전학습 가중치로 초기화합니다. 두 모델 모두
같은 4,900장, 원본 1024 해상도, 상하/좌우 반전만으로 각각 16 epoch를 완료했습니다.
메모리 압력으로 배치를 조정하고 순차 학습했으며, 중단 재개·손실 수정은
`resource_adjustment.json`, 각 모델 `run.json`과 단계별 체크포인트에 남겼습니다.
초기화·손실이 다른 두 방법의 이번 데이터 적합성을 비교한 결과이며 일반적인 모델 우열을 뜻하지 않습니다.

검증 1,050장 전체 장면(5888×3368)의 정상 오탐과 클래스별 객체 F1을 기준으로 U-Net을 선택했습니다.
`frozen_selection.json`에 모델·픽셀/점수 임계값·후처리·가중치/소스 해시를 고정한 뒤
시험 1,050장에 접근합니다. 시험에서는 저장된 타일로 잘린 라벨 대신 개별 결함의 전체 장면 정답을
다시 계산합니다. 두 모델 모두 같은 클래스·박스 IoU ≥ 0.5·일대일 매칭을 사용합니다.
U-Net 픽셀 Dice/IoU는 시험 타일에서 별도로 측정합니다. YOLO 박스를 마스크로 간주하지 않습니다.

전체 장면은 1024 타일·128 중첩으로 원본 해상도에서 처리합니다. 입력 픽셀 해시가 같은 타일의
예측 재사용은 대량 평가의 속도만 줄이며 실제 속도 측정은 파일 입력부터 캐시 없이 따로 수행합니다.
Torch 환경의 RGB 재현이 기준 생성 환경의 저장 PNG와 정확히 같은지도 검증합니다.
추론 코드에는 정상 짝·결함 레시피·정답을 전달하지 않습니다.

최종 성적·그림·재현 안내는 [모델 비교 보고서](native-comparison.md), 원시 수치는
`test_comparison.json`, `unet/test_pixel_metrics.json`, `inference_timing.json`입니다.
합성 패널 1픽셀은 촬영 이미지 3픽셀입니다. 실제 카메라의 1픽셀 선 성능으로 해석하지 않습니다.

맥 앱 v0.4는 동결된 선택 모델과 같은 `native_inference.py`를 사용합니다.
원본 기본 표시, 선택적 위치/픽셀 출력, 원본 부분 확대와 정상/불량/확인 필요/검사 불가를 지원합니다.
`scripts/inspect_native_photo.py`의 JSON-lines 상주 워커 계약은 interface.md의 OLED v3를 참고합니다.
기존 OpenCV·YOLO 앱용 스크립트와 모델 결과는 보존했습니다.

```bash
PYTHONPATH=src artifacts/yolo-env/bin/python scripts/check_native_inference.py
PYTHONPATH=src artifacts/yolo-env/bin/python scripts/check_native_inspector.py
artifacts/yolo-env/bin/python scripts/check_native_worker.py --device mps
bash scripts/build_mac_inspector.sh
```

새 환경에서 실제 사진 성능을 주장하기 전에 장비별 배율·광학 흐림·색 응답·노출·정상 편차를
측정하고, 학습에 쓰지 않은 실제 정상/불량 자료로 임계값과 성능을 확인해야 합니다.
