# 시험 기간을 제외한 최대 8주 계획

주당 최대 42 인시(리더 30 + 4명 × 3)는 상한이며 모두 개발에 쓰는 것으로 가정하지 않습니다.
초보 팀원은 매주 한 가지 작은 산출물과 실행/설명 연습에 집중하고 리더가 통합합니다.

| 기간 | 일 | 완료 기준 |
|---|---|---|
| 1주 | 환경·계약·역할, 후보 데이터 권한 및 연산 자원 조사 | 전원이 합성 명령 실행, 데이터/하드웨어 결정 기록 |
| 2주 | 사용 가능한 데이터 확보, 중복/촬영 묶음 검토, 분할 고정 | 정상 train + validation + 잠근 test 목록 및 권한 확인 |
| 3–4주 | 기존 정상 전용 학습 baseline 후보 하나(예: PatchCore) 어댑터 | 작은 실제 입력 추론, 설정/버전/가중치 출처 기록 |
| 5주 | 검증 분할에서 임계값 결정, 고정 테스트 평가 | 분할별 표본 수, 혼동행렬, 실패 사례, 재현 명령 |
| 6주 | 로컬 데모 통합 | 한 장 입력 → 점수/판정/히트맵/출처, 오류 안내 |
| 7주 | QA, 설명 자료, 사용자 실습 | 새 환경 재현, 각자 담당 코드를 설명 |
| 8주 | 일정 여유, 결과/한계 정리 | 고정 버전 로컬 시연과 최종 보고 |

**중단/축소 기준:** 2주까지 권한 있는 데이터가 없으면 실제 탐지 평가를 보류하고
합성 입출력 프로토타입으로 범위를 명확히 바꿉니다. GPU가 없거나 메모리가 부족하면 이미지 크기와
표본 수를 줄여 허용된 CPU 환경에서 가능한지 먼저 측정합니다. 유료 연산은 사용하지 않습니다.
라벨이 부족하면 가능한 정상 오탐 평가만 보고하고 결함 탐지율은 알 수 없다고 적습니다.

예상 제외 범위: 실시간 생산 검사, 다중 모델 비교 대회, 모바일 앱, 배포/인증,
실제 생산 수율 개선 주장. 시험 주간은 개발 진척을 요구하지 않습니다.
