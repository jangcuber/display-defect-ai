# 역할과 별도 세션 인계

실제 이름은 아직 정하지 않았으므로 역할로 배정합니다. 새 세션은 이 문서와 interface.md를 먼저 읽습니다.

| 역할 | 주 시간 | 주 담당 파일 | 작은 완료 단위 |
|---|---:|---|---|
| 리더 / 모델 통합 | 최대 30h | `src/display_defect_ai/`, `pyproject.toml`, 공유 계약 | 모델 어댑터, 데이터/연산 결정, 통합 리뷰 |
| 팀원 A / 데모 | 약 3h | `demo/` | 한 장 입력, 점수/미보정 표시, 히트맵 표시 |
| 팀원 B / QA | 약 3h | `tests/` | 입력 실패·계약 테스트와 재현 확인 |
| 팀원 C / 데이터 | 약 3h | `docs/data.md` | 사용 권한·촬영 조건·분할 목록 검토 |
| 팀원 D / 문서·발표 | 약 3h | `README.md`, `docs/plan.md` | 실행 안내 검증, 한계와 결과 설명 |

`scripts/generate_synthetic.py`와 합성 fixture 변경은 QA와 리더가 함께 검토합니다.
`contracts.py`와 `docs/interface.md`는 공유 경계이므로 리더가 관리합니다.
데모/QA 세션은 공유 인터페이스를 복사해서 별도로 만들지 말고 import하세요.
담당 범위 밖 수정이 필요하면 먼저 인계 메모에 제안하고 통합 담당자가 조정합니다.

## 세션 시작/종료

1. `git remote -v`, `git status --short --branch`로 저장소/분기/기존 수정을 확인합니다.
2. 인터페이스 v1을 읽고 맡은 디렉터리만 변경합니다. 기존 작업을 덮어쓰지 않습니다.
3. README의 unittest 명령과 관련 스모크 명령을 실행합니다.
4. 바뀐 파일, 실행 명령/결과, 미완료 항목, 공유 계약 변경 여부를 인계합니다.

같은 워크스페이스의 세션은 파일을 바로 읽을 수 있습니다. 별도 클라우드 체크아웃에는
커밋되지 않은 수정이 자동 전달되지 않습니다. 승인된 리뷰 브랜치와 정확한 커밋을 인계하고
각 세션은 그 커밋에서 별도 브랜치를 시작합니다. 게시 전 테스트와 공개 파일 목록을 확인합니다.
push/PR은 사용자가 승인한 범위에서만 수행하며 merge/배포는 별도 승인이 필요합니다.
